# 한국어 글쓰기 스킬 적용 규칙

한국어 자기소개서, 이력서 설명, 포트폴리오 문장, README 등 사용자에게 전달할 문서를 작성하거나 검토할 때 적용한다. 일반 대화, 코드 수정, 영어 문서에 세 스킬을 매번 일괄 실행하지 않는다.

## 필요한 스킬 선택

- 자연스러운 문장과 번역투 개선: [humanizer](../.agents/skills/humanizer/SKILL.md).
- 맞춤법·띄어쓰기·문법 검사: [grammar-checker](../.agents/skills/grammar-checker/SKILL.md).
- 용어·말투·표기 일관성: [style-guide](../.agents/skills/style-guide/SKILL.md).

전체 윤문이 필요하면 humanizer → grammar-checker → style-guide 순서로 사용한다. 맞춤법만 요청받았다면 grammar-checker만 사용한다. 사용자가 특정 스킬을 지정하면 그 범위를 따른다. 해당 SKILL.md를 읽고 필요한 references와 examples만 추가로 확인한다.

## 기존 취업 워크플로와 연결

- 프로필, 지원 절차와 검증 기준은 `CLAUDE.md` 및 기존 `.claude/` 문서가 원본이다. 글쓰기 스킬이 이를 대체하지 않는다.
- 원본에 없는 경력, 성과, 수치, 날짜, 기술 숙련도, 역할을 추가하지 않는다. 가능성을 확정 사실로 바꾸지 않는다.
- “학습했다”, “참여했다”, “직접 설계했다”처럼 책임과 경험의 수준이 달라지는 표현은 사실 확인 없이 바꾸지 않는다.
- 사용자 목소리와 문서의 격식을 유지한다. 자연스러움을 위해 맞춤법을 일부러 틀리거나 격식을 임의로 바꾸지 않는다.
- 직접 인용, 코드, URL, 파일 경로, 회사명, 자격명, 기술명과 채용 키워드를 보존한다.
- 형식을 갖춘 이력서·지원서에서는 기존 양식의 제약과 사실 검증이 우선이다. 윤문 후 기존 검증 절차를 수행한다.
- 교정과 사실 보강은 구분한다. 불명확한 내용은 원문을 유지하고 확인이 필요한 지점을 표시한다.

## Codex에서 해석할 때

원본의 `Read`, `Write`, `Edit`, `Grep`, `Glob`, `AskUserQuestion`은 사용 가능한 Codex 파일 읽기·편집·검색·질문 기능으로 해석한다. `allowed-tools`에 적힌 이름이 새로운 도구나 권한을 부여하지 않는다.

원본의 자연도 등급과 AI 작문 신호는 편집을 돕는 참고 기준이다. 작성 주체 판정이나 탐지 회피 성공을 보장하는 근거로 사용하지 않는다. 국어 규정과 문체 권장을 구분하고, 애매한 교정은 권장 사항으로 표시한다.

출처·고정 버전·라이선스는 [설치 기록](../.agents/skills/KOREAN_SKILLS_SOURCE.md)을 따른다. upstream 파일을 직접 고치기보다 이 적용 규칙을 수정한다.
